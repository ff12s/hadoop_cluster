# Чистка комментариев `ol_policy`: docstring без «почему», редкие инлайны, говорящие имена

Дата: 2026-08-02
Статус: утверждён

## Задача

Привести комментарии и docstring'и пакета `airflow/config/ol_policy` к правилу: код читается сам,
комментарий появляется только там, где без него код выглядит ошибкой. Поведение не меняется — это
правка текста и имён.

Правило, заданное владельцем репозитория:

- Docstring описывает **что делает** функция, а не почему она такая и не историю правок.
- Инлайн-комментарии редкие; комментарий оправдан только неочевидным «зачем это так сделано».
- Если без комментария непонятно — виновато имя функции, переменной или структура кода: чинить
  надо имя, а не дописывать текст.

Конвенция `CLAUDE.md` продолжает действовать в части формата: docstring есть у каждой функции,
формат PyCharm reST, поля `:param:` / `:return:` / `:raises:` сохраняются, язык русский.

## Что убирается

### 1. Module-docstring — одна строка «что в модуле»

Сейчас каждый модуль открывается эссе на 6–10 строк с обоснованиями («почему не на парсе»,
«почему только стандартная библиотека», «Airflow и сам глотает исключения колбэков»). Остаётся
одна строка назначения. Обоснования, которые стоит помнить, живут в spec-документах
`docs/superpowers/specs/` — они для этого и написаны.

| Модуль | Новый module-docstring |
|---|---|
| `__init__.py` | Точка входа cluster policy: инъекция OpenLineage в Spark-таски Airflow. |
| `parse.py` | Парс-фаза: дозапись колбэка лайниджа в `on_execute_callback` таски. |
| `callback.py` | Колбэк-фаза: резолв значений и запись conf/jars на воркере до `execute()`. |
| `variable.py` | Чтение и проверка Airflow Variable `openlineage_config`. |
| `probe.py` | Зонд наличия openlineage-spark jar в HDFS через WebHDFS. |
| `operator.py` | Совместимость с раскладками `SparkSubmitOperator` и тумблер лайниджа из `params`. |
| `logger.py` | Логгер политики с дедупликацией сообщений. |
| `utils.py` | Общие хелперы политики: идентификаторы таски, мердж CSV-значений. |
| `hadoop_conf.py` | Разбор конфигов Hadoop и резолв эндпоинтов WebHDFS. |
| `handlers.py` | Исключения политики. |

### 2. Docstring функций — summary плюс поля

Из docstring'ов уходят абзацы-обоснования. Полный список мест:

- `probe.jar_path` — абзац про то, чем грозит URI без схемы, и про игнорируемый authority.
- `probe.jar_available` — абзац про демон-поток и абзац «кэша нет намеренно».
- `probe._probe` — абзац про смысл ретрая.
- `probe._spnego_header` — абзац про ленивый импорт pyspnego.
- `callback._write` — абзацы про порядок `setattr` и про удаление `spark.jars`.
- `callback._inject` — пояснение «любой отказ молчаливый».
- `variable._cfg` / `variable._validate` — упоминания «никогда не бросает» и агрегированного warning'а
  остаются одной фразой summary, разъяснения уходят.
- `operator.passthrough_exceptions` — абзац про отсутствие `AirflowClusterPolicySkipDag` в 2.6.3 и
  про дешевизну `import_module`.
- `operator.operator_attrs` — абзац про 4.1.1 против 4.10.0.
- `operator._level_forced` — абзац про «уровень не высказался — это норма».
- `utils.task_dag` — абзац про property, бросающую у таски без DAG'а.
- `utils._csv_items` / `utils.merge_csv` — абзацы про Jinja и про смысл дедупа.
- `logger.warn_once` — абзац про состав ключа дедупликации.
- `hadoop_conf._expand` — абзац про повтор поведения `Configuration.get()`.
- `hadoop_conf.resolve_webhdfs_urls` — фраза «порядок повторяет оригинал».
- `__init__.apply_policy` / `reset_state` — абзацы про то, чем грозит исключение и кто зовёт сброс.

### 3. Инлайн-комментарии — остаётся короткий список

Оставляется ровно то, где код без комментария читается как ошибка или как случайность:

1. `callback._write_lineage` — порядок записи (`jars` раньше `conf`) как инвариант.
2. `operator` — ленивый импорт `airflow.exceptions` из-за порядка инициализации Airflow.
3. `probe` — реэкспорты `resolve_webhdfs_urls` и `_sleep` ради `monkeypatch`.
4. `hadoop_conf` — `# noqa: S314` на `ElementTree.parse` (конфиги кластера, не пользовательский ввод),
   `_MAX_DEPTH` как страховка от цикла подстановки и пометка последней ветки
   `resolve_webhdfs_urls` как фолбэка (иначе она читается дублем предыдущей).
5. `utils._csv_items` — одна фраза в docstring о том, что значение с Jinja не режется по запятой:
   без неё ветка `if "{{" in value` выглядит случайной.

Пункт 5 — единственное «почему», которое остаётся в docstring: оно объясняет существование ветки,
а не мотив автора.

Уходят: блок арифметики бюджета над `_PROBE_DEADLINE_SEC` (её удерживает ассерт в
`test_probe_deadline_covers_two_passes_over_ha_pair`), комментарии над `_Outcome` / `_ProbeOutcome`,
«форма проверяется здесь, содержимое — в `_validate`», `# причина уже названа парс-фазой`,
«Реэкспорт утилит: тесты и вызывающий код…», «Подмодули импортируются целиком ради путей…» и прочие
пересказы соседней строки.

### 4. Переименования вместо комментариев

| Было | Стало | Почему |
|---|---|---|
| `probe._Outcome` | `_EndpointOutcome` | комментарий «исход опроса одного эндпоинта» становится лишним |
| `variable._cfg` | `read_config` | «_cfg» ничего не говорит; функция читает Variable и разбирает JSON |
| `variable._validate` | `validate_config` | зовётся из `callback`, приватность мнимая |
| `callback._write` | `_write_lineage` | «write» без объекта требует docstring, чтобы понять, что пишется |
| `hadoop_conf._expand` | `_expand_vars` | раскрывает `${var}`, а не «расширяет» что угодно |

`_ProbeOutcome` имя сохраняет. Переименования затрагивают `airflow/config/tests/test_ol_policy.py`,
`tests/test-airflow.bat` (шаг 13) и упоминания имён в
`docs/superpowers/specs/2026-08-02-ol-policy-cache-removal-design.md` и одноимённом плане.

## Что не трогается

- Тексты warning'ов и ключи дедупликации — их попарную различимость проверяет
  `test_failure_reasons_are_pairwise_distinct`.
- Сигнатуры, аннотации, поведение любой ветки.
- `test_hadoop_conf.py`.
- `CHANGELOG.md` как история — там обоснованиям место; добавляется одна запись про саму чистку.

## Проверка

`python -m pytest airflow/config/tests -q` из корня `hadoop_cluster` — эталон 203 passed до и после.
Ни один тест по смыслу не меняется; правятся только имена символов, к которым тесты обращаются.
